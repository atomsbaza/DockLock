# v0.6.0 – Inactivity Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Branch:** `feature/v0.6.0-inactivity-lock`

**Goal:** Add Inactivity Lock — after a configurable period of no keyboard/mouse input, the app fires Panic Mode and, depending on settings, locks the screen. A short countdown warning appears before firing so the user can cancel by touching the keyboard or mouse. The feature backs off automatically while a display-sleep-preventing assertion is held (video playing, presentation running).

**Architecture:** New folder `VigilScreen/Features/InactivityLock/` holds four components: `IdleTrigger` (pure state-machine struct — mirrors the `ShoulderSurfingTrigger` pattern, Foundation only, no timers or system calls), `InactivityLockManager` (`@MainActor` `ObservableObject` singleton owning the timer and the two system reads — idle seconds and display-sleep assertion status), `IdleWarningPanel` (non-activating floating `NSPanel` with SwiftUI countdown content), and `InactivityLockView` (Settings pane matching the existing feature panes). Five existing files pick up the cross-cutting wiring: `SettingsStore` (4 new settings), `CloudSyncStore` (fan-out keys), `LockHistoryStore`/`LockHistoryView`/`AuditSummaryGenerator` (new `.inactivity` trigger type + icon/label + summary label), and `MenuBarManager`/`MenuBarView` (countdown surface reuse). This is the only feature in v0.6.0 — no independent task groups to parallelize; tasks are ordered bottom-up (pure logic → settings → cross-cutting wiring → system integration → UI → docs) so each task leaves the project compiling and fully passing before the next begins.

**Tech Stack:** Swift 6, SwiftUI, AppKit (`NSPanel`, `NSWorkspace`), Combine, CoreGraphics (`CGEventSource.secondsSinceLastEventType`), IOKit.pwr_mgt (`IOPMCopyAssertionsStatus`), XCTest (not Swift Testing — see testing note below)

> **Testing note:** All tests use `XCTestCase` with `@MainActor` methods. Do **not** use Swift Testing (`@Test`, `#expect`) — it crashes silently on this project's CI (iOS 26.5 SwiftData issue).

```swift
// VigilScreen/Features/InactivityLock/IdleTrigger.swift
import Foundation

/// Pure state machine deciding when to show an idle warning and when to fire.
/// No timers, no system calls — all inputs are parameters. Mirrors the
/// `ShoulderSurfingTrigger` pure-struct pattern used elsewhere in the codebase:
/// fully unit-testable in isolation, never reads `SettingsStore.shared` directly.
///
/// `IdleTrigger` decides *when* to fire; `InactivityLockManager` decides *what*
/// firing does (panic only vs. panic-and-lock) by reading `inactivityLockAction`
/// at fire time.
struct IdleTrigger {
    enum Phase: Equatable {
        case waiting, warning, fired
    }

    enum Action: Equatable {
        case showWarning(secondsRemaining: TimeInterval)
        case cancelWarning
        case fire
    }

    var phase: Phase = .waiting

    mutating func evaluate(
        idleSeconds: TimeInterval,
        displaySleepPrevented: Bool,
        panicAlreadyActive: Bool,
        timeout: TimeInterval,
        warningLead: TimeInterval
    ) -> Action? {
        // The warning cannot start before the clock does.
        let clampedLead = min(max(warningLead, 0), timeout)
        let warningThreshold = timeout - clampedLead
        let suppressed = displaySleepPrevented || panicAlreadyActive

        switch phase {
        case .fired:
            // Only reset once idle time drops below timeout again — this is
            // what prevents re-firing every tick while still idle.
            if idleSeconds < timeout {
                phase = .waiting
            }
            return nil

        case .waiting:
            if suppressed { return nil }
            if idleSeconds >= timeout {
                phase = .fired
                return .fire
            }
            if clampedLead > 0, idleSeconds >= warningThreshold {
                phase = .warning
                return .showWarning(secondsRemaining: timeout - idleSeconds)
            }
            return nil

        case .warning:
            if suppressed {
                phase = .waiting
                return .cancelWarning
            }
            if idleSeconds >= timeout {
                phase = .fired
                return .fire
            }
            if idleSeconds < warningThreshold {
                // Idle dropped (user touched the keyboard/mouse) — cancel.
                phase = .waiting
                return .cancelWarning
            }
            return .showWarning(secondsRemaining: timeout - idleSeconds)
        }
    }
}
```

```swift
/// Non-activating floating panel showing the idle-lock countdown so the user
/// can cancel by touching the keyboard or mouse. Non-activating is required:
/// the app runs with `.accessory` activation policy, and a focus-stealing panel
/// would itself count as user interaction, defeating its own purpose.
@MainActor
final class IdleWarningPanel {
    static let shared = IdleWarningPanel()
    private init() {}

    private var panel: NSPanel?
    private var hostingController: NSHostingController<IdleWarningView>?

    func show(secondsRemaining: Int) {
        if let panel, let hostingController {
            hostingController.rootView = IdleWarningView(secondsRemaining: secondsRemaining)
            positionOnPointerScreen(panel)
            panel.orderFrontRegardless()
            return
        }

        let newHostingController = NSHostingController(rootView: IdleWarningView(secondsRemaining: secondsRemaining))
        let newPanel = NSPanel(
            contentRect: NSRect(x: 0, y: 0, width: 260, height: 90),

            backing: .buffered,
            defer: false

        newPanel.level = .floating
        newPanel.isOpaque = false
        newPanel.backgroundColor = .clear
        newPanel.hasShadow = true
        newPanel.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .ignoresCycle]
        newPanel.contentViewController = newHostingController
        newPanel.isReleasedWhenClosed = false

        panel = newPanel
        hostingController = newHostingController

            y: frame.maxY - panelSize.height - 40
```

### Task 6: InactivityLockManager — timer, system reads, fire logic

**Files:**
- Create: `VigilScreen/Features/InactivityLock/InactivityLockManager.swift`
- Modify: `VigilScreen/App/AppDelegate.swift`

> **What this task does:** `InactivityLockManager` is the `@MainActor` `ObservableObject` singleton that owns the timer and performs the two system reads (`CGEventSource.secondsSinceLastEventType` for idle seconds, `IOPMCopyAssertionsStatus` for the display-sleep assertion), plus a third read — `CGSessionCopyCurrentDictionary` / `kCGSessionOnConsoleKey` — folded into the same `panicAlreadyActive` input passed to `IdleTrigger.evaluate` (keeping `IdleTrigger` itself free of system calls, and avoiding a second suppression input). It publishes `isCountingDown`/`secondsRemaining` for the menu bar and popover countdown surface (Task 8), and arms a single timer for the interval until the next decision point rather than polling every second: per-second ticks only while a warning is on screen, a coarse 10 s re-check while suppressed (display-sleep assertion held or panic already active) or after firing, and an exact single-shot arm for the next decision point otherwise — consistent with `ScreenShareDetector`'s zero-CPU-at-idle approach.
>
> **No unit tests are written for this file.** Per the approved spec's "Not unit-testable" list, the idle-time and assertion system reads, timer scheduling across sleep/wake, and `LockEngine.lockScreen()` cannot be exercised in CI. `IdleTrigger` (Task 1) already covers every branch of the decision logic in isolation. This task wires the real system integration; a manual verification checklist follows this task.
>
> `CGSessionCopyCurrentDictionary` is public CoreGraphics API — declared in `CGSession.h` since macOS 10.3 — so it's called directly below, with no manual binding required. `kCGSessionOnConsoleKey` is the public constant for the console-session dictionary key, used below instead of a hand-typed string literal.

- [ ] **Step 1: Create `InactivityLockManager.swift`**

```swift
// VigilScreen/Features/InactivityLock/InactivityLockManager.swift
import AppKit
import Combine
import CoreGraphics
import IOKit.pwr_mgt

@MainActor
final class InactivityLockManager: ObservableObject {
    static let shared = InactivityLockManager()

    @Published private(set) var isCountingDown = false
    @Published private(set) var secondsRemaining: Int = 0

    private var trigger = IdleTrigger()
    private var armedTimer: Timer?
    private var cancellables = Set<AnyCancellable>()
    private var hasLoggedAssertionQueryFailure = false

    private let settings = SettingsStore.shared

    private init() {
        settings.$inactivityLockEnabled
            .sink { [weak self] enabled in
                guard let self else { return }
                if enabled {
                    // Seed in the fired phase rather than fresh .waiting. By the
                    // fired → waiting rule in IdleTrigger, the feature cannot fire
                    // until idle time first drops below the timeout — this protects
                    // both the just-enabled real-world case (the Mac may already be
                    // idle past the timeout when the toggle flips) and app-hosted
                    // test runs (SettingsStoreTests toggles this key synchronously;
                    // without this seed, a real panic+lock could fire mid-test-suite
                    // if the Mac's actual idle time already exceeds the timeout).
                    var seeded = IdleTrigger()
                    seeded.phase = .fired
                    self.trigger = seeded
                    self.tick()
                } else {
                    self.disable()
                }
            }
            .store(in: &cancellables)

        // Settings changed mid-countdown re-evaluate immediately rather than
        // waiting out the previously-armed timer.
        Publishers.CombineLatest3(
            settings.$inactivityLockTimeout,
            settings.$inactivityWarningLead,
            settings.$inactivityLockAction
        )
        .dropFirst()
        .sink { [weak self] _, _, _ in
            guard let self, self.settings.inactivityLockEnabled else { return }
            self.tick()
        }
        .store(in: &cancellables)

        // Timers don't fire during system sleep — re-evaluate on wake rather
        // than trusting a timer that may be hours stale.
        NSWorkspace.shared.notificationCenter
            .publisher(for: NSWorkspace.didWakeNotification)
            .sink { [weak self] _ in
                guard let self, self.settings.inactivityLockEnabled else { return }
                self.tick()
            }
            .store(in: &cancellables)
    }

    // MARK: - Timer loop

    private func tick() {
        guard settings.inactivityLockEnabled else { return }

        let idleSeconds = Self.idleSeconds()
        // Guard at point of use: an out-of-range inbound cloud value (e.g. 0) must not produce an instant fire.
        let timeout = max(60, settings.inactivityLockTimeout * 60)
        let warningLead = settings.inactivityWarningLead
        let displaySleepPrevented = isDisplaySleepPrevented()
        let panicAlreadyActive = PanicModeManager.shared.isActive || isSessionLocked()
        let suppressed = displaySleepPrevented || panicAlreadyActive

        if let action = trigger.evaluate(
            idleSeconds: idleSeconds,
            displaySleepPrevented: displaySleepPrevented,
            panicAlreadyActive: panicAlreadyActive,
            timeout: timeout,
            warningLead: warningLead
        ) {
            perform(action)
        }

        scheduleNextCheck(idleSeconds: idleSeconds, timeout: timeout, warningLead: warningLead, suppressed: suppressed)
    }

    private func perform(_ action: IdleTrigger.Action) {
        switch action {
        case .showWarning(let remaining):
            isCountingDown = true
            secondsRemaining = Int(remaining.rounded())
            IdleWarningPanel.shared.show(secondsRemaining: secondsRemaining)

        case .cancelWarning:
            isCountingDown = false
            secondsRemaining = 0
            IdleWarningPanel.shared.hide()

        case .fire:
            isCountingDown = false
            secondsRemaining = 0
            IdleWarningPanel.shared.hide()
            LockHistoryStore.shared.record(.inactivity)
            PanicModeManager.shared.triggerPanic()
            if settings.inactivityLockAction == .panicAndLock {
                LockEngine.lockScreen()
            }
        }
    }

    private func scheduleNextCheck(idleSeconds: TimeInterval, timeout: TimeInterval, warningLead: TimeInterval, suppressed: Bool) {
        armedTimer?.invalidate()

        // Per-second ticks only while a warning is on screen, so the countdown
        // stays accurate. While suppressed (display-sleep assertion held or panic
        // already active) or after firing, fall back to a coarse 10s re-check —
        // there's no event to wait on, but polling every second for the entire
        // duration of a suppression would burn CPU for no benefit. Everywhere
        // else, arm a single timer for the exact next decision point instead of
        // polling — zero CPU at idle, consistent with ScreenShareDetector's
        // approach. No blanket coarse floor across all non-warning phases: at a
        // short warningLead (e.g. 10s), that would push the warning past the
        // fire time.
        let interval: TimeInterval
        if trigger.phase == .warning {
            interval = 1.0
        } else if suppressed || trigger.phase == .fired {
            interval = 10.0
        } else {
            let clampedLead = min(max(warningLead, 0), timeout)
            let nextDecision = clampedLead > 0 ? (timeout - clampedLead) : timeout
            interval = max(1.0, nextDecision - idleSeconds)
        }

        armedTimer = Timer.scheduledTimer(withTimeInterval: interval, repeats: false) { [weak self] _ in
            self?.tick()
        }
    }

    private func disable() {
        armedTimer?.invalidate()
        armedTimer = nil
        trigger = IdleTrigger()
        isCountingDown = false
        secondsRemaining = 0
        IdleWarningPanel.shared.hide()
    }

    // MARK: - System reads

    private static func idleSeconds() -> TimeInterval {
        // kCGAnyInputEventType is exposed to Swift as CGEventType(rawValue: ~0).
        CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType: CGEventType(rawValue: ~0)!)
    }

    private func isDisplaySleepPrevented() -> Bool {
        var statusPtr: Unmanaged<CFDictionary>?
        let result = IOPMCopyAssertionsStatus(&statusPtr)
        guard result == kIOReturnSuccess, let statusPtr else {
            logAssertionQueryFailureOnce()
            return false // fail toward "no assertion held" — the security-forward default
        }
        guard let status = statusPtr.takeRetainedValue() as? [String: Any] else {
            logAssertionQueryFailureOnce()
            return false // unexpected dictionary shape — same fail-open default as a query error
        }
        let preventsIdleDisplaySleep = (status[kIOPMAssertionTypePreventUserIdleDisplaySleep as String] as? Int ?? 0) > 0
        let preventsAnyDisplaySleep  = (status[kIOPMAssertionTypeNoDisplaySleep as String] as? Int ?? 0) > 0
        return preventsIdleDisplaySleep || preventsAnyDisplaySleep
    }

    private func logAssertionQueryFailureOnce() {
        guard !hasLoggedAssertionQueryFailure else { return }
        hasLoggedAssertionQueryFailure = true
        print("[VigilScreen] InactivityLockManager: IOPMCopyAssertionsStatus failed — assuming no display-sleep assertion held")
    }

    private func isSessionLocked() -> Bool {
        guard let info = CGSessionCopyCurrentDictionary() as? [String: Any] else {
            return false // fail toward "not locked" — same default direction as the assertion query
        }
        let onConsole = info[kCGSessionOnConsoleKey as String] as? Bool ?? true
        return !onConsole
    }
}
```

```swift
// VigilScreen/Features/InactivityLock/InactivityLockView.swift
import SwiftUI

struct InactivityLockView: View {
    @ObservedObject private var settings = SettingsStore.shared
    @ObservedObject private var manager = InactivityLockManager.shared

    var body: some View {
        Form {
            enableSection
            if settings.inactivityLockEnabled {
                tuningSection
                actionSection
                liveStatusSection
            }
        }
        .formStyle(.grouped)
        .navigationTitle("Inactivity Lock")
    }

    // MARK: - Sections

    @ViewBuilder private var enableSection: some View {
        Section {
            Toggle("Enable Inactivity Lock", isOn: $settings.inactivityLockEnabled)
        } footer: {
            Text("Locks your screen after a period of no keyboard or mouse input. Backs off automatically while video is playing or a presentation is running.")
                .foregroundStyle(.secondary)
        }
    }

    @ViewBuilder private var tuningSection: some View {
        Section {
            HStack {
                Text("Lock after")
                Spacer()
                Slider(value: $settings.inactivityLockTimeout, in: 1...60, step: 1)
                    .frame(width: 160)
                Text("\(Int(settings.inactivityLockTimeout)) min")
                    .monospacedDigit()
                    .frame(width: 50, alignment: .trailing)
            }
            HStack {
                Text("Warning before locking")
                Spacer()
                Slider(value: $settings.inactivityWarningLead, in: 0...30, step: 1)
                    .frame(width: 160)
                Text(settings.inactivityWarningLead == 0 ? "Off" : "\(Int(settings.inactivityWarningLead))s")
                    .monospacedDigit()
                    .frame(width: 36, alignment: .trailing)
            }
        } header: {
            Text("Tuning")
        } footer: {
            Text("The warning shows a countdown panel before locking so you can cancel by touching the keyboard or mouse. Set to 0 to lock immediately with no warning.")
                .foregroundStyle(.secondary)
        }
    }

    @ViewBuilder private var actionSection: some View {
        Section {
            Picker("On timeout", selection: $settings.inactivityLockAction) {
                ForEach(InactivityLockAction.allCases, id: \.self) { action in
                    Text(action.displayName).tag(action)
                }
            }
            .pickerStyle(.radioGroup)
        } header: {
            Text("Action")
        } footer: {
            Text("Panic Mode always triggers first, hiding your apps. Choose whether the screen also locks.")
                .foregroundStyle(.secondary)
        }
    }

    @ViewBuilder private var liveStatusSection: some View {
        if manager.isCountingDown {
            Section {
                HStack {
                    Label("Locking in", systemImage: "timer")
                        .foregroundColor(.orange)
                    Spacer()
                    Text("\(manager.secondsRemaining)s")
                        .monospacedDigit()
                        .bold()
                        .foregroundColor(.orange)
                }
            } header: {
                Text("Live Status")
            }
        }
    }
}
```

> **What this task does:** Wires `InactivityLockManager.shared.$isCountingDown`/`$secondsRemaining` into the same two surfaces Proximity Lock already uses — the menu bar status item title (`MenuBarManager.updateMenuBarTitle`) and the popover row (`MenuBarView`).
>
> One adjustment beyond a literal copy-paste of the existing mechanism: `updateMenuBarTitle`'s current guard (`showStats, BluetoothMonitor.shared.pairedDeviceUUID != nil`) exists because the surface was built for Bluetooth stats, and hides the countdown entirely when no device is paired or the "Show live Bluetooth stats" toggle is off. Inactivity Lock is explicitly built for users **without** a paired Bluetooth device (or without BLE hardware at all), and it has its own `inactivityLockEnabled` toggle — gating its countdown behind the unrelated Bluetooth-stats setting would hide it from exactly the audience the feature targets. Rather than widen the Bluetooth guard, `updateMenuBarTitle` checks `InactivityLockManager.shared.isCountingDown` first and returns before that guard ever runs, leaving the existing Bluetooth stats path (and its original guard) untouched. This is a minimal, spec-unspecified adjustment needed to make "reuse the existing surface" actually work for the feature's target users — flagged here rather than made silently.
>
> No unit tests — both files are pure UI wiring (Combine → AppKit / SwiftUI), verified by build + the manual checklist above.

```markdown
## Inactivity Lock (`Features/InactivityLock/`)
- `IdleTrigger`: pure struct, Foundation only — mirrors the `ShoulderSurfingTrigger` pattern. `evaluate(idleSeconds:displaySleepPrevented:panicAlreadyActive:timeout:warningLead:)` returns `.showWarning`/`.cancelWarning`/`.fire`/`nil` and owns a `waiting → warning → fired` phase machine. `warningLead` is clamped to `timeout` inside `evaluate` so the warning cannot start before the clock does.
- `InactivityLockManager`: `@MainActor` singleton owning the timer + three system reads — `CGEventSource.secondsSinceLastEventType` (idle seconds), `IOPMCopyAssertionsStatus` (`kIOPMAssertionTypePreventUserIdleDisplaySleep` is the live signal current macOS populates; `kIOPMAssertionTypeNoDisplaySleep` is checked defensively as a legacy alias current macOS never actually populates in that dictionary; fails toward "no assertion held" on query error, logged once), and the public `CGSessionCopyCurrentDictionary()`/`kCGSessionOnConsoleKey` (session-locked check, folded into the `panicAlreadyActive` input rather than a separate one). Arms a single timer for the next decision point: per-second ticks only while a warning is on screen, a coarse 10 s re-check while suppressed (assertion held or panic already active) or after firing, and an exact single-shot arm for the next decision point otherwise. Re-evaluates immediately on settings change and on `NSWorkspace.didWakeNotification` (timers don't fire during sleep).
- `IdleWarningPanel`: non-activating floating `NSPanel` (`.nonactivatingPanel`, `.floating`) — required because the app is `.accessory`, and an activating panel would itself count as user input. Shown on the `NSScreen` containing `NSEvent.mouseLocation`.
- `InactivityLockView`: Settings pane, same `Form`/`.formStyle(.grouped)` pattern as `ProximityView`/`ShoulderSurfingView`. First `Picker`-backed setting in the codebase (`inactivityLockAction`).
- On fire: records `.inactivity` in `LockHistoryStore`, calls `PanicModeManager.shared.triggerPanic()`, and `LockEngine.lockScreen()` only if `inactivityLockAction == .panicAndLock`. Countdown surfaces reuse the menu bar title + popover row that Proximity Lock uses (`MenuBarManager`/`MenuBarView`).
```
