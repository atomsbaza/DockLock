Inactivity Lock

A visual walkthrough of the new trigger: where it sits among the app's existing paths to Panic Mode, how its state machine decides when to fire, how the evaluation loop is wired, and the guard that keeps it from misfiring during passive viewing.

04

The false-trigger guard

macOS idle time only counts input — a keystroke or a mouse move. A full-screen video, a slideshow, a long unscrolled document all read as fully idle even while someone is actively watching. Two guards keep Inactivity Lock from firing on that.

Guard 1

Display-sleep assertion

A held assertion suppresses the timer entirely. Video players, Keynote, and presentation software all hold one while active — the most common false-trigger case never reaches warning.

Guard 2

Warning overlay

Catches what Guard 1 can't: someone reading a long document with no assertion held. Default 10s, configurable 0–30s. Any input cancels it — 0 turns it off.

If the assertion query fails, it's treated as "no assertion held" and evaluation proceeds — security-forward by default, with the warning overlay as the escape hatch.
