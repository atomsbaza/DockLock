# Design Spec: Privacy Audit Log Summary + Shoulder Surfing False Positive Learning (v0.5.0)

**Date:** 2026-06-01
**Branch:** `feature/v0.5.0-audit-shoulder-learning`
**Status:** Approved

---

## Overview

Two independent features shipping together in v0.5.0:

1. **Privacy Audit Log Summary** — on-demand natural-language summary of existing `LockHistoryStore` events using Apple's Foundation Models (on-device LLM, macOS 26 + Apple Silicon only).
2. **Shoulder Surfing False Positive Learning** — weighted face detection to eliminate photo/TV/mirror false positives, plus a feedback loop (implicit + explicit) that nudges the sensitivity slider after repeated false triggers.

Both features are local-first, zero new entitlements, zero network calls. The shoulder surfing improvement is a staged approach: better heuristics now (v0.5.0), Core ML classifier later (v0.6.0).

---

## Feature 1: Privacy Audit Log Summary

### What it does

A "Summarize session" button in `LockHistoryView` generates a 2–3 sentence plain-English summary of recent privacy events. Example output: *"During the past 3 hours, Panic Mode fired twice — once triggered by a shoulder surfer, once manually. Proximity Lock engaged once when your phone left range. No intruder captures."*

The summary is ephemeral — generated on demand, not stored. Each tap regenerates it.

### Architecture

**New file:** `VigilScreen/Features/History/AuditSummaryGenerator.swift`

```
@MainActor final class AuditSummaryGenerator {
    static let shared = AuditSummaryGenerator()

    // Available only on macOS 26+ Apple Silicon with model downloaded.
    var isAvailable: Bool  // #available(macOS 26, *) && SystemLanguageModel.default.isAvailable

    func generate(from events: [LockEvent]) async throws -> String
}
```

`generate(from:)` formats events into a timestamped plain-text list and sends to `LanguageModelSession.respond(to:)`. Returns the model's response string.

**Prompt construction:** Events are formatted as:
```
2026-06-01 14:32 — Panic Mode triggered (manual)
2026-06-01 14:35 — Shoulder surfer detected
2026-06-01 15:01 — Proximity Lock engaged
```
Prompt suffix: *"Summarise this privacy session in 2–3 plain sentences."*

**UI changes — `LockHistoryView.swift`:**
- "Summarize session" toolbar button, rendered only when `AuditSummaryGenerator.shared.isAvailable && !events.isEmpty`
- On tap: button replaced by `ProgressView` spinner
- On completion: result displayed in a `.sheet`
- On error: sheet shows *"Summary unavailable — try again."*

### Availability gating

| Condition | Result |
|---|---|
| macOS < 26 | Button not compiled in (`#available` guard) |
| macOS 26, Intel | Button hidden (`isAvailable = false`) |
| macOS 26, Apple Silicon, model not downloaded | Button hidden |
| macOS 26, Apple Silicon, model available | Button shown |

No fallback text, no placeholder UI on unsupported hardware.

### Error handling

`LanguageModelSession.respond` failures (timeout, model unavailable mid-session) are caught and surface *"Summary unavailable — try again."* in the result sheet. No crash, no silent failure, no empty sheet.

### Files changed

| File | Change |
|---|---|
| `Features/History/AuditSummaryGenerator.swift` | New — ~60 lines |
| `Features/History/LockHistoryView.swift` | +~25 lines (button, sheet, loading state) |

## Feature 2: Shoulder Surfing False Positive Learning

### What it does

**Part A — Weighted detection (v0.5.0):** Filters `VNFaceObservation` results by confidence and bounding box area before counting faces. Small, low-confidence detections (photos, TVs, mirrors) are excluded from the trigger count. Only "credible" faces increment `consecutiveMultiFaceFrames`.

**Part B — Feedback loop (v0.5.0):** Implicit and explicit false positive signals feed a counter in `SettingsStore`. After 3 false positives, a dismissable banner in `ShoulderSurfingView` offers to reduce sensitivity.

**Part C — Core ML classifier (v0.6.0, deferred):** The false positive signals from Part B become labeled training data. Not built now; the feedback infrastructure is the v0.6.0 bridge.

### Part A: Weighted Detection

**Change in `ShoulderSurfingDetector.swift`:**

Replace the current `captureOutput` delegate which passes a raw `count`:
```swift
let count = request.results?.count ?? 0
Task { @MainActor in self.handleFaceCount(count) }
```

With `[VNFaceObservation]` passed to a new `handleObservations(_:)`:
```swift
let observations = (request.results ?? []) as [VNFaceObservation]
Task { @MainActor in self.handleObservations(observations) }
```

**Credibility filter (constants in `ShoulderSurfingDetector`):**
```swift
private let minFaceConfidence: Float = 0.7
private let minFaceArea: Float = 0.02   // normalized width × height
```

A face is credible when `observation.confidence >= minFaceConfidence` AND `(observation.boundingBox.width * observation.boundingBox.height) >= minFaceArea`.

`handleObservations` computes `credibleCount` from filtered observations, then delegates to the existing `handleFaceCount(credibleCount)` unchanged. All trigger, countdown, and auto-release logic remains identical.

**Why these thresholds:** `0.7` confidence rejects low-quality detections (poster, angled mirror). `0.02` normalized area (~14% of either frame dimension) rejects faces that are too far or too small to be a realistic over-the-shoulder threat. Both are named constants — easy to tune.

### Part B: Feedback Loop

**False positive signals:**

*Implicit:* Add `private var triggerTime: Date?` to `ShoulderSurfingDetector`. Set when `didAutoTrigger = true`. In the existing `$isActive` sink, when panic goes inactive with `didAutoTrigger == true`: if `Date().timeIntervalSince(triggerTime ?? .distantPast) < 5`, call `recordFalsePositive()`. Piggybacks the existing observer — no new subscription.

*Explicit:* `.shoulderSurfer` events in `LockHistoryView` render a "Not a real threat" button. Tapping calls `ShoulderSurfingDetector.shared.recordFalsePositive()`.

**Counter storage — `SettingsStore.swift`:**
```swift
@Published var shoulderSurfingFalsePositiveCount: Int = 0
// Persisted: UserDefaults["shoulderSurfingFPCount"]
// NOT synced to iCloud — device-local learning only
```

**`recordFalsePositive()` in `ShoulderSurfingDetector`:**
Increments `SettingsStore.shared.shoulderSurfingFalsePositiveCount` on `@MainActor`.

**Banner — `ShoulderSurfingView.swift`:**
Shown when `shoulderSurfingFalsePositiveCount >= 3`:
> *"3 false triggers detected — reduce sensitivity?"*

Two actions:
- **Reduce** — `shoulderSurfingSensitivity = max(0.0, shoulderSurfingSensitivity - 0.25)`, reset count to 0
- **Dismiss** — reset count to 0

Both reset the counter. Banner reappears only after 3 more false positives.

## Testing

### `AuditSummaryGeneratorTests.swift` (new)
- Prompt construction: given a known `[LockEvent]` array, assert the formatted string contains correct timestamps and trigger labels
- No live Foundation Models calls in tests — mock or stub `LanguageModelSession`
- Availability: `isAvailable` returns false when `#available` guard fails (compile-time; test on macOS 15 CI)

### `ShoulderSurfingDetectorTests.swift` (additions)
- Single large credible face → no trigger (credibleCount = 1)
- Two faces both below area threshold → no trigger (credibleCount = 0)
- Two faces both below confidence threshold → no trigger
- Two credible faces → trigger after `triggerThreshold` frames
- Mixed: one credible + one non-credible → credibleCount = 1, no trigger
- Implicit false positive: `triggerTime` set, panic releases within 5s → `recordFalsePositive()` called
- Implicit non-false-positive: panic releases after 10s → `recordFalsePositive()` not called

### `SettingsStoreTests.swift` (additions)
- `shoulderSurfingFalsePositiveCount` increments to 3 → banner condition true
- Reduce action: sensitivity decremented by 0.25, count reset to 0
- Sensitivity floor: at 0.0, reduce action keeps it at 0.0
- Dismiss action: count reset to 0, sensitivity unchanged

## What is NOT in v0.5.0

- Core ML classifier for shoulder surfing (v0.6.0)
- Feature vector logging / training data collection (v0.6.0 design)
- iCloud sync for false positive counter (intentionally local-only)
- Audit log persistence (summary is ephemeral by design)
- New event types in LockHistoryStore (clipboard reads, camera activations)
